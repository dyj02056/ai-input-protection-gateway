꼭 알아 두세요. 설치만 하면 아무것도 막지 않고 알려 주기만 합니다. 전송 차단·승인은 설정에서 직접 켜야 동작합니다. 이 도구는 형식을 보고 찾기 때문에 감지되지 않았다고 안전한 것은 아닙니다. 시험할 때는 가짜 값만 쓰세요.

4

안내창 사용하기

입력창에 민감정보가 들어오면 오른쪽 위에 안내창이 뜹니다.

  • 감지 항목 마스킹 — 민감한 부분만 [전화번호]처럼 가립니다. 문단·줄바꿈은 그대로 둡니다.
  • 실행 취소 — 마스킹 직후 한 번 되돌릴 수 있습니다.
  • × — 안내를 닫습니다. 같은 감지가 계속되는 동안은 다시 뜨지 않습니다.

브라우저 도구 모음의 확장 아이콘을 누르면 지금 탭이 보호 대상인지 보입니다. 아이콘의 배지 색으로 마지막 판정(초록=감지 없음, 주황=마스킹·승인 필요, 빨강=차단 판정)도 알 수 있습니다.

설치 없이 탐지 결과만 보고 싶다면 로컬 탐지 데모에서 같은 탐지 코드를 브라우저 안에서 실행해 볼 수 있습니다.

조직 서버 연결 (선택)

회사가 정책을 통일하고 승인·기록을 관리하고 싶을 때만 필요합니다. 서버를 연결하지 않으면 확장은 네트워크 요청을 전혀 하지 않습니다. 서버가 받는 것은 정책 요청, 그리고 사용자가 별도로 동의한 감사 이벤트·승인 요청뿐이며, 입력한 글과 파일은 받지 않습니다.

먼저 헷갈리기 쉬운 점: 키 본체와 해시

값생김새어디에 넣나요
키 본체43자 정도의 무작위 영문·숫자 (한 번만 보여 줌)직원용 → 확장 옵션 / 관리자용 → 콘솔 로그인 화면
해시 줄PDP_..._SHA256=이름=64자리서버 설정 파일 .env (해시를 콘솔에 넣으면 거부됩니다)

관리자: 서버 준비하기

1

키 두 개를 만듭니다. 각 명령이 키 본체와 해시 줄을 출력합니다. 키 본체는 따로 안전하게 보관하세요.

py tools/server.py setup                           # 처음 한 번: 서버 준비
py tools/server.py newkey --name my-user           # 직원용 키 만들기
py tools/server.py newkey --admin --name my-admin  # 관리자 키 만들기
2

gateway-core/server/.env 파일을 만들어 해시 줄만 넣습니다. 형식은 이름=해시이고 공백·따옴표는 넣지 않습니다. 키 해시는 일반용과 관리자용이 서로 달라야 합니다.

# gateway-core/server/.env  (직접 만드는 파일. 저장소에는 올라가지 않습니다)
PDP_API_KEYS_SHA256=my-user=<직원용 키의 해시 64자리>
PDP_ADMIN_KEYS_SHA256=my-admin=<관리자 키의 해시 64자리>
3

서버를 시작합니다. .env를 바꿨다면 서버를 껐다 켜야 합니다.

py tools/server.py run          # 서버 시작: http://127.0.0.1:8787
# 콘솔: http://127.0.0.1:8787/console

관리자: 관리 콘솔 쓰기

http://127.0.0.1:8787/console에 접속해 관리자 키 본체를 입력합니다(일반 키는 거부됩니다). 키는 화면 메모리에만 있고 저장되지 않아, 새로고침하면 다시 입력합니다.

탭할 수 있는 일
승인함직원의 승인 요청을 보고 건별로 승인·거절 (대기 건수 표시, 15초마다 자동 갱신)
정책현재 정책에서 시작해 항목별 조치를 바꿔 새 버전 만들기(바로 적용 선택), 문제가 생기면 이전 버전으로 되돌리기
감사 로그확장이 보낸 이벤트(최근 100건)와 체인 검증으로 조작 여부 확인
관리 기록누가 언제 정책을 바꾸고 무엇을 승인·거절했는지, 마찬가지로 체인 검증

직원: 확장 연결하기

  1. 확장 옵션 → 조직 정책 서버에 서버 주소(예: http://127.0.0.1:8787)와 직원용 키 본체를 입력합니다.
  2. 연결하고 정책 받기를 누르고, 브라우저가 서버 접근 허용을 물으면 허용합니다.
  3. "상태: 연결됨"과 적용 중인 정책(예: default v1)이 보이면 성공입니다. 이후 안내 문구가 "조직 정책(v1) 판정이 …"로 바뀝니다.
  4. 콘솔에서 정책을 바꾸면 옵션의 지금 동기화를 눌러 바로 받을 수 있습니다(자동으로는 사이트를 열 때 10분 간격).

서버 주소는 https만 쓸 수 있습니다(개발용 localhost·127.0.0.1은 http 가능). 연결 끊기를 누르면 저장된 주소·키·정책과 동의 설정이 지워집니다.

관리자 승인 흐름

옵션에서 로컬 정책 적용 + 승인 확인 단계 + 관리자 승인 요청을 모두 켜고 서버를 연결했을 때, 판정이 승인 필요인 글은 이렇게 처리됩니다.

  1. 전송이 멈춥니다. 보내기를 눌러도, 다시 눌러도 통과하지 않습니다. 안내창에 업무 목적 선택·사유 칸·승인 요청 보내기가 나옵니다.
  2. 요청합니다. 목적(고객 응대·문서 검토·코드 작업·데이터 분석·기타)을 고르고, 필요하면 짧은 사유를 적습니다. 서버에는 범주 ID·목적·사유만 갑니다. 사유에는 이름·전화번호 같은 개인정보를 쓰지 마세요.
  3. 관리자가 처리합니다. 콘솔 승인함에서 승인 또는 거절합니다.
  4. 결과가 안내창에 나타납니다. 5초 간격으로 확인해 "승인되었습니다" 또는 거절(처리 메모 포함)로 바뀝니다.
  5. 승인되면 딱 한 번 통과합니다. 내용을 바꾸지 말고 보내기를 다시 누르세요.
상황결과
승인 후 글자를 하나라도 바꿈막힘. 바뀐 내용으로 다시 요청해야 합니다 (원래대로 되돌리면 다시 유효)
같은 승인으로 두 번 보내려 함두 번째는 막힘 (승인은 한 번만 유효)
거절됨 / 만료됨통과하지 않음. 요청이 4시간 안에 처리되지 않거나, 승인 후 30분 안에 쓰지 않으면 만료됩니다(다시 요청하면 됩니다)
서버가 응답하지 않음통과하지 않고 이유를 안내. 급하면 옵션에서 승인 요청 스위치를 끄면 기존 "5초 안에 다시 누르면 전송" 방식으로 돌아감

"내용이 같은가"의 비교는 이 탭의 메모리 안에서만 합니다. 비교용 값은 서버로 보내지 않고 저장하지 않으며, 탭을 닫거나 새로고침하면 사라집니다.

자주 묻는 질문

서버가 제 입력을 보나요?
아니요. 서버로 가는 것은 감지된 종류·조치·시각·정책 버전, 승인 요청 시의 업무 목적·짧은 사유뿐입니다. 입력한 글, 파일(이름 포함), 사이트 주소는 보내지 않습니다.
설치하자마자 전송이 막히나요?
아니요. 기본은 안내만 합니다. 막는 기능은 직접 켜야 합니다.
감지가 100% 정확한가요?
아닙니다. 형식 기반이라 오탐과 누락이 있고, 이름·주소는 아직 감지하지 못합니다. 감지되지 않았다고 안전한 것은 아닙니다.
실제 AI 사이트에서 검증되었나요?
자동 시험(가상 환경·헤드리스 Chrome)까지 통과했지만, 각 사이트의 실제 화면에서의 동작은 직접 확인이 필요합니다. 사이트가 바뀌면 입력창·답변 위치 인식이 달라질 수 있습니다.
서버를 회사 밖에서도 쓸 수 있나요?
현재 서버는 로컬 개발·시연용입니다. TLS, 속도 제한, 사용자별 키·SSO가 없으니, 운영하려면 HTTPS를 처리하는 프록시 뒤에 두고 서버 README의 "운영 전에 해야 할 일"을 따르세요.
